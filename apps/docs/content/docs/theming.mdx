A Syntara theme is generated, not drawn. Six brand inputs go through the theme engine, which builds colour ramps, assigns semantic roles for light and dark, fixes every contrast failure it finds, and writes CSS variables. Components only ever read those variables.

A new brand changes values, never names — so no component knows which brand it renders ([ADR-005](https://github.com/anujpatel06/syntara/blob/main/docs/adr/005-token-tiers-and-naming.md)).

## A brand is six inputs

Primary colour, an optional accent, neutral temperature, shape, type pair and default density. This is Harbor’s whole brand:

<TenantBrandJson id="harbor" />

The engine keeps the brand hex exact where contrast allows and moves labels, rings and text first when it doesn’t. Every move is logged in a sentence, e.g. the house brand of this site:

<HouseAdjustments />

To generate a theme yourself:

```ts
import { generateTheme, toCSS } from '@syntara/theme-engine';

const theme = generateTheme({
  name: 'Acme',
  primary: '#0f766e',
  neutral: 'cool',
  shape: 'soft',
  typePair: 'technical',
  density: 'comfortable',
});

const css = toCSS(theme, { selector: '[data-syntara-theme="acme"]' });
```

## Your own font

Instead of a type pair, a brand can name its own font: a Google font, or its own files, for body text and optionally a different one for headings. Syntara accepts it only if it passes six measured checks ([ADR-051](https://github.com/anujpatel06/syntara/blob/main/docs/adr/051-custom-brand-fonts.md)):

1. It loads: Google has it under that name, or the file is a real font.
2. Regular, Medium, Semibold and Bold are real weights, not faked by the browser.
3. Every character in Syntara's test text for the brand's language is drawn by the font itself. Latin is always checked; ₹ only for Hindi brands.
4. No letter's ink is cut off, at every size from 12 to 72px, Regular and Bold, on standard and high-density screens.
5. The line spacing it needs stays within the limits Syntara already ships: 1.8 for headings and labels, 1.9 for paragraphs.
6. Its lower-case letters are at least 0.45 of its size, so 12px text stays readable.

`npx syntara init --font <name>` runs the checks in your Chrome or Edge and stores what they measured in `syntara.brand.json`, under `font`. The engine reads the measured line spacing from there; it never guesses it. The type pair stays in the file: it still sets the mono font.

## ThemeScope

Token CSS keys off `data-syntara-theme`, `data-syntara-scheme` and `data-syntara-density`, and they must sit on the same element. `ThemeScope` puts them there and gives the subtree the theme’s canvas, text colour and body font. Its `locale` prop also sets React Aria’s locale, `lang` and `dir` — see [RTL](/docs/rtl).

```tsx
import { ThemeScope } from '@syntara/react';

<ThemeScope theme="harbor" scheme="dark" density="compact">
  <ClaimForm />
</ThemeScope>
```

### How token files are scoped

`toCSS` takes the selector for a theme’s base block and appends the mode attributes to it. `@syntara/tokens` builds two kinds of file:

- `dist/<id>/tokens.css` uses `:root`, so that tenant is the whole app’s theme. Its modes key off `<html>`, e.g. `:root[data-syntara-scheme="dark"]`.
- `dist/syntara.css` uses `[data-syntara-theme="<id>"]` for every tenant, so a tenant applies only inside an element or `ThemeScope` that names it.

## Several tenants on one page

Scopes nest and sit side by side, each with its own tenant, scheme and density. This site is the example: the chrome uses the house theme on `:root`, and every preview is a `ThemeScope` you can switch between tenants.

```tsx
<div className="compare">
  <ThemeScope theme="vela"><PaymentCard /></ThemeScope>
  <ThemeScope theme="qamar" locale="ar-AE"><PaymentCard /></ThemeScope>
</div>
```

Dialogs, popovers and menus render in a portal at the end of `<body>`, outside any scope. When one opens, it copies the scope attributes, `dir` and `lang` from the element that opened it — so a dialog opened from a Harbor-dark preview is Harbor-dark (<AdrLink n="012" />). ## Adding a tenant

1. Create `tenants/<id>/brand.json` with the six inputs, and `content.json` with the tenant’s copy, locale and direction.
2. Run `pnpm tokens`. It fails if any contrast check fails, so a broken theme can’t ship.

For a tenant with its own font, measure it into the brand file: `node scripts/check-font.mjs <Google name> --script=<latin|arabic|devanagari> --out=tenants/<id>/brand.json --brand="$(cat tenants/<id>/brand.json)"`. It writes `font` only if every check passes. `pnpm tokens` then also writes `fonts.css`, with the tenant's own font files copied beside it.

That’s all. No component changes. `pnpm tokens` writes the new tenant’s files to `@syntara/tokens`, and this site picks it up on its next build, in the preview toolbar and the tables above.
