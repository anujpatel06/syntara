Syntara installs two ways: with one npm command, or by copying a component’s source files into your project (<AdrLink n="011" />). Both give you the same components and the same tokens. Every component page has the exact steps.

You need React 19 and a bundler that handles CSS — Next.js and Vite both do out of the box. Syntara doesn’t use Tailwind, so it works with or without it.

## With npm

Run one command in your app's folder. It is the whole setup.

<PackageCommand dlx="syntara init" />

It does four things:

1. **Asks about your brand.** A few questions, each with a suggestion: press Enter to take it. No brand guidelines? Pick a starting look instead. Built a theme on the [Themes](/themes) page? Its **Use in your app** command gives the same answers, so only the name is asked.
2. **Writes your theme.** `syntara-theme.css` is a light and dark theme that passes every WCAG 2.2 AA contrast check. `syntara.brand.json` keeps the answers it was built from.
3. **Installs Syntara.** It offers to run your project's own package manager to add the `syntara` package. Add `--no-install` to skip this.
4. **Adds it to your app.** It finds your entry file (`src/main.tsx` in Vite, `app/layout.tsx` or `pages/_app.tsx` in Next.js) and adds two style imports and a `ThemeScope` around your app. It shows you the change and asks before it saves. Add `--no-edit` to skip this and do it by hand.

Changed `syntara.brand.json` by hand? Run `npx syntara build` to rebuild the theme.

Icons come from `syntara/icons` and the theme engine from `syntara/theme-engine`.

### What init added, or doing it by hand

If you used `--no-edit`, or want to know what changed, these are the two steps `syntara init` does in your entry file.

<Steps>

### Import the CSS once

At your app root — `app/layout.tsx` in Next.js, `src/main.tsx` in Vite — import the one stylesheet (every built-in brand’s tokens, then the component styles), then your brand’s.

<CodeBlock title="src/main.tsx">

```tsx
import 'syntara/styles.css';
import './syntara-theme.css';
```

</CodeBlock>

The tokens are scoped to `[data-syntara-theme="<id>"]`, one block per brand. Skipped `init`? Leave out the second line and use a built-in brand, such as `vela`.

### Wrap your app in a ThemeScope

`theme` is your brand's id: the one `syntara init` printed, also in `syntara.brand.json`.

```tsx
import { Button, ThemeScope } from 'syntara';

export default function App() {
  return (
    <ThemeScope theme="my-brand" scheme="dark">
      <Button>Continue</Button>
    </ThemeScope>
  );
}
```

</Steps>

### One piece at a time

`syntara` is a bundle of the separate packages, which are still published on their own: `@syntara/react` (components),
`@syntara/tokens` (token CSS), `@syntara/icons` and `@syntara/theme-engine`. Install them separately when you only need
one, for example the tokens in an app that isn't React:

<PackageCommand add="@syntara/react @syntara/tokens" />

```tsx
import '@syntara/tokens/dist/syntara.css';
import '@syntara/react/styles.css';
```

If your app only ever shows one brand, import `@syntara/tokens/dist/<id>/tokens.css` instead of `dist/syntara.css`; it
puts that tenant on `:root`. Each component also has its own entry point, e.g.
`import { Button } from '@syntara/react/ui/button'`.

## By hand

Every component page has a **Manual** tab with the full source of each file.

1. Install the npm packages the component lists — usually `react-aria-components` (44 components) and `@syntara/icons` (23); the two date components also need `@internationalized/date`.
2. Copy its `.tsx` and `.module.css` files into one folder, such as `components/ui`.
3. Copy any Syntara components it uses into the same folder. Files import each other as `./button`, so the folder can live anywhere.
4. Load a token file once at your app root. Take one from `@syntara/tokens`, or copy the **CSS** export on the [Themes](/themes) page.

The files are yours from then on. They are CSS Modules that read `--syntara-*` variables, and nothing else.

## Set the theme

Token CSS keys off three attributes on one element — `<html>` for the whole app, or a `ThemeScope` for part of it.

```html
<html data-syntara-theme="vela" data-syntara-scheme="auto" data-syntara-density="compact">
```

With a single tenant’s `tokens.css`, the tenant is already on `:root`. Put the scheme and density attributes on `<html>`. To give regions of a page different tenants or schemes, load `syntara.css` and pass `theme` to each `ThemeScope`.

See [Theming](/docs/theming), [Dark mode](/docs/dark-mode) and [Density](/docs/density) for the rest.
